# Выбор сценария по риску

Выбери самый короткий путь, на котором проявляется нужный отказ. Начни с публичного входа, через который достигается риск. Масштаб стенда выбирай по тому, какая часть действительно должна работать.

| Обещание | Как воспроизвести условие | Что проверить |
|---|---|---|
| Потерянный ответ не приводит к двойному платежу | Тестовый провайдер фиксирует принятую операцию, затем возвращает тайм-аут. Клиент повторяет операцию с тем же ключом. Рабочая логика повтора включена. | Итоговая сумма, одно фактическое списание по ключу и согласованное состояние заказа. Сетевых попыток может быть несколько. |
| Последняя единица достанется одному покупателю | Два независимых участника работают с одним остатком в тестовой БД нужного типа. Барьер подводит их к месту конкуренции. У ожидания есть предел. | По цене ошибки проверь число успешных резервов, ожидаемый исход проигравшего и итоговый остаток. Два последовательных вызова гонку не воспроизводят. |
| После частичного сбоя обработчик восстанавливается | В контролируемой точке после записи результата и до подтверждения доставки прерви обработку тестового сообщения. Дай очереди повторно доставить то же сообщение. | Результат сохранился один раз, сообщение завершено по контракту. Подмена, возвращающая успех до записи, этот случай исключает. |
| Отзыв права действует в установленный момент | Тестовый сотрудник открывает запись. Право редактирования отзывается. Тот же пользователь сохраняет изменения из открытой формы. Заранее установи из контракта, когда действует отзыв. | Видимый отказ и прежнее состояние записи. Контроль с действующим правом должен успешно изменить запись, иначе сломанная запись для всех пройдёт отрицательный тест. |
| В выгрузке видны положенные данные | В своей организации подготовь две различимые записи, в другой — одну. Получи файл обычным способом от лица тестового пользователя. | Состав файла равен ожидаемым записям, включая кратность, если повторы значимы. Это различает корректную, пустую, неполную и чужую выдачу. |
| Выбор сохраняется после обновления страницы | Выполни действие в браузере, дождись видимого состояния, обнови страницу и прочитай значение. | Для обещания сохранности нужна настоящая граница записи и чтения. С подменённым API можно отдельно проверить отображение ошибки. |

**Когда достаточно двух чисел.** Скидка 10 ₽ действует от 100 ₽ включительно. Заказы на 99,99 ₽ и 100 ₽ различают преждевременную скидку, неверный порог и неправильный размер скидки на пороге. Используй представление денег проекта. Отдельный браузерный сценарий ради этой формулы избыточен.

**Когда уместен генератор.** Для сортировки проверь порядок и сохранение элементов с их количеством. Для внешнего формата добавь известный совместимый пример к проверке записи и обратного чтения. Для многих допустимых последовательностей резервов и отмен используй простую модель остатка и сохраняй минимальный воспроизводимый пример. Если в среде есть навык `property-based-testing`, подключи его для выбора свойства и генератора данных.

**Каким инструментом пользоваться.** Начни со штатного тестового запуска проекта. Для багфикса пригодится приём «падение — исправление — успех» из TDD. Матрица API помогает вспомнить пропущенное условие, браузерный инструмент — увидеть результат на экране, а контрактный тест — проверить совместимость потребителя с поставщиком. Добавляй зависимость или MCP, когда иначе останется конкретный непроверенный риск.
