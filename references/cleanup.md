# Разбор подозрительного теста

| Что привлекло внимание | Как установить проблему | Что изменить или оставить |
|---|---|---|
| Ожидаемое значение вычисляет функция продукта или её копия | При неверном округлении тем же способом меняются обе стороны сравнения. | Возьми разобранный пример или независимый эталон. Общий helper для подготовки входа допустим. |
| Проверяется только HTTP 200, тип объекта или непустой ответ | Подставь неверный по смыслу ответ того же типа. | Проверь обещанные поля и эффекты. Для проверки доступности сервиса кода ответа может хватить. |
| Пустой цикл, условный assert или «любое исключение» | Операция может вообще не выполниться, а тест всё равно пройдёт, либо исключение возникнет при подготовке. | Создай различимые данные. Проверь состав выдачи или ожидаемый тип отказа в точке действия. |
| Заглушки и приватные вызовы определяют весь результат | Убери решение из рабочей логики в изолированном примере. Если тест всё равно зелёный, найди, где ответ был заготовлен. | Оставь проверяемый участок реальным. У внешнего отправщика полезно проверять адресата, содержание и кратность, когда отправка сама является договором. |
| Большой снимок или привязка к порядку шагов | Прочитай разницу. Какое требование нарушено? Изменился ли публичный формат? | Сузь ожидание до обещанного свойства. Сохрани снимок для договорного файла, визуальной регрессии или другого проверяемого формата. |
| Много похожих случаев либо много assert | Сравни, какое нарушение замечает каждый случай. Проверь границы, тип вызывающего клиента, состояние и стоимость диагностики. | Объедини одинаковые проверки параметрами, если это улучшает читаемость. Сохрани независимые гарантии, даже если их код похож. |
| Фиксированный sleep, автоматический повтор, нестабильность только в группе | Запусти узкую группу в условиях сбоя. Ищи общий изменяемый объект, зависимость от очередности, часов, случайности или завершения фоновой работы. | Жди события с предельным временем, управляй часами, фиксируй контрпример. Повтор помогает диагностике. Для временного пропуска укажи, какая защита потеряна. |
| Быстрый unit-тест дублирует действие из дорогого E2E | Пропустит ли быстрый тест разрыв между частями? Что случится со всей проверкой при сломанной интеграции? | Перенеси таблицу вариантов на дешёвый уровень и оставь один путь через настоящее соединение, если оно несёт отдельный риск. |
| Метрика выросла, агент обещает «полное покрытие» | Посмотри, что собрал и выполнил runner. Проверь существенный риск, пропуски, причину красного результата. | Укажи проверенное поведение. Для проверки ценности навыка сравни на одинаковых исторических задачах пойманные дефекты, ложные падения и время. |

Для спорного удаления сравни сохраняемый и удаляемый тесты на существенном контрпримере. Если нет безопасного способа подтвердить дублирование, зафиксируй неопределённость. Вывод о прогоне делай только по фактически выполненной проверке.

При укрупнении набора сравни сбор тестов и выбор по маркерам до и после переноса. Найди обращения к прежним путям в командах проекта. При замене моков БД покажи, что новая интеграционная проверка действительно выполняет запрос. При удалении теста исторической миграции установи, какое состояние он защищал: создание ограничения с нуля и сохранение старых записей при обновлении требуют разных исходных данных.
